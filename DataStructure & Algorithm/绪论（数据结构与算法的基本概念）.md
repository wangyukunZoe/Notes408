# 绪论（数据结构与算法的基本概念）

# Intro

数据结构和算法探讨的是计算机运行过程中，数据与存储结构的关系问题。优秀的存储结构和精巧的算法可以最大限度的发挥硬件的潜力和性能。但是在这之前，熟悉有关相关基本概念仍然重要

### 1. 数据

数据是信息的载体，是描述客观事物的属性、字符、以及所有能被计算机程序接收和处理的对象的集合。数据是构成计算机程序运行的基本元素。

### 2. 数据元素

数据元素是数据的基本单位，一个数据元素可以包含多个数据项，数据项是构成数据元素的不接分割的最小单位。举例：一条学生记录就是一个数据元素，里面由学号、姓名、性别等数据项组成。

### 3. 数据类型

数据类型是指具有相同属性和性质的一组操作的集合，其中数据类型分为以下三种类型

1. 原子类型  其值不可再分的数据类型（类似于操作系统中的原语——执行相关操作必须一气呵成，不可中断。）
2. 结构类型  数值可以进一步划分成若干不同成分（分量）的类型
3. 抽象数据类型(ADT) 一个数学模型以及定义在该模型上的一种操作——通常是对数据的某种抽象，规定了数据的取值范围，数据的结构类型以及可执行的操作集合。

数据结构是相互之间存在一种或多种特定关系的数据元素的集合。数据结构包括三方面的内容：逻辑结构、存储结构、数据的运算。

数据的逻辑结构与存储结构密不可分：算法的设计取决于所采用的逻辑结构、算法的实现依赖于所选择的存储结构。

上述知识点不重要，考试很少考察，但对于数据结构的理解以及后续内容的理解非常关键。这里简单举个例子🌰

假如你创办了一个超市，每天都会收到大量的，来自不同地区、不同种类、不同数量的商品。你不可能把大量的商品随便放吧？！除非你是在搞路边摊或小卖铺。

作为一个超市，如何在海量商品中迅速找到顾客想要的商品，帮助他节省大量时间可以很好的提升顾客的购物体验。即便最小的便利店，爽快的店主也会在开业前把商品分门别类的摆放好，静待迎客。哪有那些办法可以让用户迅速找到自己想要的商品呢？

1. 给商品分类，但类别别太多
2. 给商品类别提供鲜明的表示，让顾客知道进店后该往哪里走，直达商品区域
3. （开一段时间后）记录当地顾客最爱买哪些，提前摆出来供用户挑选

如果这三个例子对应数据结构的话，例子🌰a（商品类别）对应了数据元素，每个商品就是一个数据元素内的数据项。每个商品类别可以化成一个子类别，包含在一个大类别中。那个大类别就可以理解为数据结构中的数据类型。

相信你去过图书馆吧，为了方便读者快速的找书，在硕大的图书馆找书跟大海捞针差不多，因此不可能把大量的书籍随意摆放，或一本挨着一本放。现实的情况是，图书馆会按照每本书的所属的属性和类别，分门别类的按序摆放，并通过不同的编号方便读者快速的检索，从而找到图书。其中每一本书就可以对应数据结构中的数据，而每本书中关于书的书名、出版社、书的简介等内容构成书的属性，每项书的属性就可以对应数据结构中的数据项。而由这些书的属性构成的一条条图书记录则可以对应数据结构中的数据元素。那么再扩展一些，如果把同类型的图书记录汇总起来，就可以形成一个书的类比，比如计算机类（TS），文学类（I），机械⚙️类（TU）等等，这些类型就可以对应数据结构中的数据类型。而如何在可以在这些复杂的结构中找到图书，需要不同的书类建立联系，方便图书的查找。这种联系可能是具有父子级别的树🌳状联系，或者是具有关系网的图🗺状联系；在这个基础上再通过高效的算法精确查到一本书便是一件触手可得的事情。

相信现在通过上述简述，已经明白了数据结构中最基本的概念，下面是数据结构中非常重要的三大概念：逻辑结构、存储结构、数据的运算。

# I. 数据结构的三要素

### 1. 数据的逻辑结构

逻辑结构是指数据元素之间的逻辑关系，与数据在计算机中的存储方式无关，数据的逻辑结构分为线性结构和非线性结构。线性表是典型的线性结构，树、图集合是非线性结构。

其中“有序表”就属于一种逻辑结构。

### 2. 数据的存储结构

存储结构是指数据结构在计算机中的表示方式，也称为物理结构。常见的存储结构：顺序存储、链式存储、索引存储和散列存储。

注意⚠️：数据的逻辑结构独立于数据的存储结构

|      | **存储特点**                                                     | **是否能随机存储**                  | **存储密度** | **优点**             | **缺点**                                    |
| ---- | ------------------------------------------------------------ | ---------------------------- | -------- | ------------------ | ----------------------------------------- |
| 顺序存储 | 挨着放，将逻辑上相邻的元素存储在物理位置也相邻的存储单元中。元素间的关系由存储单元的邻接关系来体现            | ✅                            | 高        | 存储密度高，可以实现随机存储     | 因为要求使用连续的存储空间，会导致较多的外部碎片                  |
| 链式存储 | 逻辑上相邻的元素存储在物理位置上可以不相邻。元素间的关系通过指针指示元素的存储地址来表示其逻辑关系            | ❎，只能顺序存取。并且每个元素会因存储指针而占用额外空间 | 低        | 不会出现碎片，能充分利用所有存储单元 | ❎，只能顺序存取。并且每个元素会因存储指针而占用额外空间              |
| 索引存储 | 在存储元素信息的同时为此建立索引表。索引表中的每一项为索引项，通常包含关键字和地址。类似于<key1, key2>键值对 | ✅                            |          | 检索速度快              | 需要开辟额外的空间存储索引表，且增加和删除数据需要更新索引表，会产生额外的时间开销 |
| 散列存储 | 根据元素的关键字直接计算出其存储地址，也称为哈希存储。                                  |                              |          | 检索、插入和删除元素的操作都非常快。 | 但如果散列函数设计的不当会可能产生冲突，解决冲突会增加时间和空间成本        |

### 3. 数据的运算

数据的运算包括定义和实现两个方面。<mark style="background:#fff88f">*数据运算的定义针对逻辑结构说明运算的功能</mark>；数据运算的实现针对存储结构，描述具体的操作步骤。

# II. 算法和算法评价

### 4. 算法的基本特性

1. 有穷性  算法必须执行有限的步骤后结束🔚，且每一步都能在有限的时间内完成
2. 确定性  算法中的每条指令都必须有明确的含义，相同的输入只能产出相同的输出
3. 可行性  算法中所描述的操作可以通过已经实现的基本运算在有限次数内完成
4. 输入和输出 输入——算法可以有零或多个输入；输出——算法必须至少有一个输出，且输入和输出之间存在特定的关系

### 5. 设计一个好的算法应该满足的目标

1. 正确性 算法可以正确的解决问题
2. 可读性  算法结构清晰，便于修改和维护
3. 健壮性（鲁棒性）对非法或异常能够做出正确处理，不至于程序崩溃或产生不可预测的结构（常见与边界值异常与输入数据的类型异常）
4. 高效率和低存储量需求 效率是指算法的执行时间，存储量需求是指执行过程中所需的最大存储空间。两者与问题规模有关。

### 6. （重要）算法效率的度量

评价一个算法优劣，正确性是基本要求，算法运行的效率是衡量算法优劣的关键指标。

#### 6.1 时间复杂度

时间复杂度描述算法执行时间随问题规模n 增大而变化的趋势，是关于n的渐进函数。算法的执行时间通常由语句频度（某条语句的执行次数）来衡量。算法的时间复杂度通常用 O(n) 来表示。

算法的实际运行时间不仅依赖于问题规模 n，还收到输入数据初始状态的影响，同一种算法在不同实例下的运行时间差异可能很大

其中关于算法的时间复杂度还可以进行如下更细的划分：

1. 最好时间复杂度：在最有满足条件（最有利于算法）的运行时间。
2. 最坏时间复杂度：在最不不满足条件（最不利于算法）的运行时间。
3. 平均时间复杂度：所有输入等概率出现时的期望运行时间（输入数据等概率的情况）

通常以最坏时间复杂度作为衡量算法效率的评价标准。因为它提供了算法运行时间的最坏情况（可能的最慢情况，也称为确定性上界）

其中算法的性能问题，只有在n非常大的时候才会暴露出来

为了更快分析出一段代码的时间复杂度，通常可以用以下办法

1. 如果有多层嵌套循环♻️，只需要关注最深层循环在程序执行中会执行多少次
2. if-else 结构的复杂度取决于if的条件判断复杂度和两个分支部分的复杂度，***总体复杂度取三者中最大的***
3. 加法原则，记时间复杂度为T(n)， 若两段算法分别有时间复杂度T1(n)=O(f1(n))和T2(n)=O(f2(n))，则，T1(n) + T2(n) = O(f1(n)) + O(f2(n)) = O(max(f1(n),  f2(n)))
    
    两段代码顺序执行，则总时间复杂度取两者中的最高阶项
    
4. 乘法原则，记时间复杂度为T(n)， 若两段算法分别有时间复杂度T1(n)=O(f1(n))和T2(n)=O(f2(n))，则，T1(n) * T2(n) = O(f1(n)) * O(f2(n)) = O(f1(n) · f2(n)))
    
    若一段代码嵌套在另一段的内部中，则时间复杂度为两者之积
    

举例：

```cpp
// 适用于加法原则的实例
a{
	b{ }
	c{ }
} // 时间复杂度为O(n^2)，适用于加法原则

// 适用于减法原则的实例
a{
  b{
	  c{}
  }
}   //  时间复杂度为O(n^3)，适用于乘法法原则
```

#### 6.2 空间复杂度

空间复杂度s(n) 表示算法在运行过程中所需的额外存储空间，是问题规模 n的函数，记为

 $S(n) = O(g(n))$

程序执行时所需要的空间包括：指令、常数和变量（与 n无关）输入数据、数据存储的辅助空间（函数调用栈、栈帧、临时数组、指针pointer等）。其中输入数据所占空间只取决于问题本身，与算法无关，不计入空间复杂度。在分析空间复杂度时，只需要关注算法额外使用的辅助空间。举例：某个算法用数组实现的静态顺序表创建了长度为n的数组，则其空间复杂度O(n)

若算法仅使用常量级的额外空间，则其称为原地工作，算法空间复杂度为O(1)

提示：程序运行时的内存需求：无论问题规模怎么变，算法运行所需的内存空间都是固定常量，算法空间复杂度为s(n) = O(1) 

另外关于函数递归调用的情况，首先找到递归调用的深度X与问题规模 n之间的关系 x = f(n)，x的数量级O(x)就是算法空间复杂度S(n).

> 注意： 这里的时间复杂度与空间复杂度是指算法的，要与计算机组成原理的“时间局部性”和“空间局部性”做区分

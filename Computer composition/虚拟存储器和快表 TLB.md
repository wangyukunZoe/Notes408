## 1. 什么是虚拟存储器

*虚拟存储器是一种由硬件和系统软件共同实现的存储管理机制，利用主存(内存、Cache等物理内存)和辅存(磁盘)构成一个逻辑上连续且容量巨大的地址空间。例如在运行类似于 Adobe Photoshop或Blander 3D这样的图形处理软件或 3D 建模软件时，经常会用到虚拟内存技术来在运行时加载所需要的图形处理文件，加快图像的编辑和模型建模的处理。*

值得注意的是，这套机制对于**应用程序员来说是透明的**，程序可以按照此虚拟空间进行编写，不需要关心实际主存容量或数据在主存中的物理位置。

### a. 虚拟存储的基本概念

概述：虚拟存储器将程序的地址空间(虚拟地址空间或逻辑地址空间)与主存的物理地址空间分离。用户程序使用的地址称为虚地址(也称为逻辑地址)。实际主存单元的地址称为实地址(也称为物理地址)。一般情况下，虚拟地址空间大于＞物理地址空间。

CPU 处理虚拟地址的逻辑：
+ CPU 使用虚拟地址访问内存时，OS 系统首先判断该虚拟地址对应的数据是否已经贮存在主存中
+ 如果已经驻留，就通过地址变换机制将其转换成**实地址**，CPU 可以直接访问对应的主存单元
+ 如果没有驻留，就触发缺页(或缺段)异常，由 OS 将包括该地址的整个页或段从**辅存**调入主存，之后 CPU 再进行访问。
+ 如果主存已经满🈵，就需要用**替换算法**选择一个页面进行置换

#### ‼️ 提示：关于虚拟存储器只能使用回写法的原因。

首先，虚拟存储器借鉴了 Cache 的思想，将辅存中频繁访问的数据缓存在主存中。由于辅存的访问延迟极高，比如说是磁盘等外部存储设备，**每次写操作都同步更新辅存中的数据一定是不中的。** 因此，系统会采用类似于**回写的策略**：
##### 采用于类似于回写的策略
当页面被修改时，标记为脏页；只有在该页面被**置换出主存的时候**，如果它为**脏页**，才将其写回辅存。这样做显著降低了 I/O 开销。

另外这样做，虚拟存储器的分页机制允许任一虚页装入主存中任意可用的物理页框，就像全相联映射一样，这样可以更好的提高主存利用率，并支持高效的地址重定位。

## 2. 页式虚拟存储器

页式虚拟存储器以页为基本单位。主存空间和虚拟地址空间均被划分为大小相同的页。主存中的页称为物理页，一般我们把它们称为**实页，页框 page frame**。虚拟地址空间的页被称为虚拟页，一般叫做**虚页**。页表记录了📝每个虚页在主存中的映射位置，通常常驻内存。

*这里跟 OS 操作系统的关系密切，操作系统将很快更新这一节*
### a. 页表的组成

主存中的页表一般由：有效位、脏位、引用位组成。

| 组成          | 作用                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------- |
| 有效位（也称为装入位） | 表示对应的虚页是否已经调入主存，**如果为 1，表示该页已调入主存**，页表项保存其物理页号。**如果为 0，表示未调入** ，页表项通常存放在该页在外存，也就是磁盘中的地址。 |
| 脏位（也称为修改位）  | 表示页面是否被修改过。在采用回写法策略的虚拟存储系统中，置换页面时需要根据脏位决定是否需要将主存 Cache 的数据写回磁盘                           |
| 引用位（也称为使用位） | 记录📝页面是否被访问过，主要用于实现基于历史的页面替换算法（CLOCK 或 LRU 算法）                                           |

#### 关于数组的分页存放，缺页分析的处理过程——2025 年考过大题

这种题目一般都分为三种情况：🎯有效位为 1，页驻留主存；有效位不为 0，发生缺页异常，主存已满，需要选择一个页面进行置换。
先说第一种情况：
+ 若 CPU 访问第 1 页，有效位为 1，说明该页面已驻留主存。地址转换部件将虚拟地址->物理地址，CPU 即可访问对应的物理页中的数据。
+ 若 CPU 访问第 5 页，有效位为 0，则发生缺页异常，系统需要调用缺页处理程序。该程序根据页表项中的外存地址，将该页从磁盘中调入一个空闲的物理页框
+ 如果主存满了，则需要选择一个页面进行置换。由于系统采用回写策略，换出页面时根据脏位决定是否写回磁盘。缺页处理完成以后，更新页表中的相应项目。

#### 页式存储器的优点与缺点：

+ 优点：页面大小固定，页表的结构简单，调入操作比较方便。

+ 缺点：程序大小通常不是**页长的整数倍，导致最后一页产生内部碎片**。另外，页面是物理划分的单位，缺乏逻辑意义。因此在程序模块化、保护和共享方面不如段式存储更灵活。**但是随着操作系统 OS 需要支持的主存和磁盘外设的容量越来越大，乃至内存有1TB 的情况，现在的 OS 普遍采用页式存储策略来满足虚拟内存的需要。**

### b. 地址转换
#### 虚拟地址结构分析

程序生成的地址为虚拟地址，CPU 在执行指令时，必须先把它转换为物理地址才能访问主存中的指令和数据。
虚拟地址分为两部分，高位为**虚页号**，低位为**页内偏移**。物理地址同样分为高位物理页号和低位页内偏移。因为页面大小相同，两者的页内偏移量完全一致。虚拟地址到物理地址的转换通过页表实现，页表是一张存放在主存中的虚页号和物理页号的映射表。
#### 虚拟地址 -> 物理地址

首先，系统通过页表基址寄存器指向当前进程的页表始地址。
地址转换时，首先从虚拟地址中提取虚页号，以此作为索引查找页表项。如果页表项的有效位为 1，则从中取出物理页号，并与虚拟地址中的页内偏移量进行拼接，形成最终的物理地址。
如果有效位为 0，则会发生缺页异常，需要由操作系统 OS 进行缺页处理。

### c. 块表 TLB

*由地址转换的过程可知，每次方寸需先访问主存中的页表来获取物理页号，再访问主存取得实际数据，因此采用虚拟存储机制后，**平均访存次数增加，性能下降。***

#### 关于TLB的硬件实现

TLB 的实现是按照程序访问的局部性原理进行设计的。（注意此处联想一下，Cache 主存替换算法中的 LRU 最近最少使用算法也是依据局部性原理而来的。）
根据程序访问的局部性原理，在一段时间内 CPU 往往集中访问少数页面。如果将这些页面对应的**页表项**缓存在由**高速 SRAM 构成**的快表 TLB 中，则可在地址转换时避免访问主存中的页表，从而显著提升效率。相应地，主存中的页表通常被称为慢表(page)。

#### TLB映射方式，地址划分和标记字段的索引

TLB 的工作原理类似于 Cache，但要注意一点昂，***TLB 中没有直接映射的方式***，因为直接映射的随机性太强，命中率很低，不适用于TLB快表这种需要快速进行数据交换的形式，效率太低。
TLB 通常采用全相联映射和组相联映射。TLB 表项包含虚拟页号(作为页号)和对应的**物理页号**及**控制位**（有效位、脏位等）。在全相联映射下，TLB 标记即为完整的虚拟页号；在组相映射下，虚拟页号的高位作为标记，低位作为组索引。

### d. 具有TLB和Cache的多级存储系统

#### 具有TLB的虚拟存储系统的地址变换过程

2018 年的统考真题曾经详细的考过这个问题，这个问题需要重视
试题中是一个具有 TLB 和 Cache 的多级存储系统，其中 Cache 采用 2 路组相联映射方式。CPU 给出一个 32 位的虚拟地址，TLB 采用全相联映射结构，每项均配置一个比较器。
在进行地址映射时，将虚拟地址中的虚页号和所有 TLB 项的标记字段并行比较。若某一项匹配且有效位为 1，则 TLB 命中🎯，直接从中获取实页号，完成地址转换。
如果TLB 没有命中❌，需要访问主存中的页表(慢表)以获取对应的页表项，完成地址转换后将其装入 TLB。若 TLB 已满🈵，则需要执行替换算法。
获取物理地址后，Cache 根据映射方式将其划分为标记、组号和块内地址三个字段。首先利用组号定位到对应的 Cache 组(一般还是需要先由分配出来的数据区域，除以主存块号算出 Cache 行号，然后再与 X路去取模算出 Cache 组)。再将该组中各 Cache 行的标记与物理地址的标记字段进行比较，如果某一行匹配且有效位为 1，则 Cache 命中，再根据块内地址取出对应的数据送至 CPU。

实际上，通过 TLB 缓存频繁访问的页表项，系统避免了每次地址转换都访问主存页表，从而在引入虚拟存储器的同时，几乎不降低访存性能。



## 总结：关于 TLB、Cache、和 Page 三种缺失组合的分析

##### 关于TLB、Cache和Page三种缺失的可能组合情况

CPU 一次访存操作可能涉及 TLB、页表、Cache 和主存及磁盘的访问。CPU 访存过程有以下三种缺失情况：
+ TLB 缺失：要访问的虚页号不在 TLB 中
+ Cache 缺失：要访问的主存块不在 Cache 中
+ Page 缺失：要访问的页面不在主存中（当然这种情况就需要到磁盘上去调取，损失的时间就比较多）
并且，有一个很重要的事：***TLB 中保存是 Cache 内数据的副本，并不是 Cache 把数据整体都移动到 TLB 快表中去了***。这也就意味着，TLB 作为页表项的缓存，Page 缺失时，TLB 也必然会缺失。
同理，Cache 是主存的副本，因此 Page 缺失时，Cache 中也不可能有对应的数据。

| 序号  | TLB  | Page | Cache | 说明                                        |
| --- | ---- | ---- | ----- | ----------------------------------------- |
| 1   | 命中🎯 | 命中🎯 | 命中🎯  | TLB 命中🎯则 Page 一定命中，信息ℹ️在主存，就可能再 Cache 中  |
| 2   | 命中🎯 | 命中🎯 | 缺失❌   | TLB 命中🎯则 Page 一定命中，信息ℹ️在主存，也可能不在 Cache 中 |
| 3   | 缺失❌  | 命中🎯 | 命中🎯  | TLB 缺失❌则 Page 可能命中，信息ℹ️在主存，就可能在 Cache 中   |
| 4   | 缺失❌  | 命中🎯 | 缺失❌   | TLB 缺失❌则 Page 可能命中，信息ℹ️在主存，也可能不在 Cache 中  |
| 5   | 缺失❌  | 缺失❌  | 缺失❌   | TLB缺失❌则 Page 也可能缺失❌，信息ℹ️不在主存，也一定不在Cache 中 |
第一种组合最好😄，不需要访问主存
第二种和第三种需要访问一次主存
第四种需要访问两次主存
第五种就会发生缺页异常现象，需要访问磁盘😭，并至少访问两次主存。

这里需要注意的是，Cache 缺失处理由硬件自动完成；不需要软件。缺页处理由操作系统 OS 通过“缺页异常处理程序”实现，具体的 step 包括：调入所需要的页面、更新页表等。
TLB 缺失可由硬件处理，也可以由软件处理。

## 3. 段式虚拟存储器

*这个简单了解即可，现代 OS 操作系统为了提升虚拟内存和增强硬件兼容性已经很少用了*

段式虚拟存储器中的段是按程序的逻辑结构划分的，各个段的长度因程序而异。虚拟地址分为两部分：段号和段内地址。虚拟地址到物理地址的变换由段表实现。段表是程序的逻辑段与其在主存中存放位置的对照表，每行记录某个段的段号、有效位、段起点和段长等信息。由于段长度可变，段表中必须给出各段起始地址与段长。
CPU 根据虚拟地址访存时，首先从虚拟地址中提取段号，并根据段表基地址找到对应的段表项。然后检查该段表项的有效位：若为1，表示该段己调入主存；若为 0，表示该段不在主存中。当该段已调入主存时，从段表读出其在主存中的起始地址，与段内地址相加，得到对应的物理地址。
由于段是程序逻辑结构所决定独立部分，因此分段对程序员来说是不透明的；而分页对程序员是透明的，程序员编写程序时无须美心程序如何分页。
段式虚拟存储器的优点是：段的边界与程序的自然逻辑边界一致，具有良好的逻辑独立性，便于程序编译、管理、修改和保护，也易于实现多道程序间的段共享。缺点是：段长度可变，主存分配困难，段间容易产生外部碎片，难以有效利用，造成存储空间浪费。
## 4. 段页式虚拟存储器

在段页式虚拟存储器中，程序先按逻辑结构分段，每段再划分为固定大小的页，主存空间也划分为大小相等页，程序对主存的调入和调出仍以页为基本交换单位。每个程序对应一个段表，每段对应一个页表。虚拟地址由段号、段内页号和页内地址三部分组成。CPU 根据虚地址访存时，首先用段号查找段表，获得该段对应的页表起始地址：接着以段内页号为索引访问页表，取出实页号；最后将实页号与页内地址拼接，形成物理地址。

段页式虚拟存储器的优点是兼具页式和段式的优点，既支持按段进行共享和保护，又避免了

段式存储的外部碎片问题。缺点是在地址变换过程中需要两次查表，系统开销较大。

## 5. 虚拟存储器和 Cache 的比较

| Cache 与虚拟存储器                                   |                                                                             |
| ---------------------------------------------- | --------------------------------------------------------------------------- |
| 相同点                                            | 不同点                                                                         |
| 最终目标都是提高系统性能，两者都体现了容量、速度、价格（成本💰）的梯度           | Cache 主要解决了 Cpu 与主存之间的速度差异，而虚拟存储器为了解决主存容量                                   |
| 都把数据块划分为小信息块作为基本交换的单位，虚拟存储器的页通常比 Cache 块大得多    | Cache 完全由硬件实现，对所有程序员透明；虚拟存储器由 OS 操作系统和硬件共同实现，对应用程序员透明，但其管理机制对 OS 操作系统开发者不透明 |
| 都涉及到地址映射、替换算法和更新策略等问题                          |                                                                             |
| 都是基于局部性原理，采用“快速缓存”的思想，将活跃数据放到 Cache 高速缓存等高速部件中 |                                                                             |

#### 关于两种方式开销的对比🆚：

|                     | Cache                               | 虚拟存储系统                                      |
| ------------------- | ----------------------------------- | ------------------------------------------- |
| 不命中时的性能影响不同         | Cache 命中🎯不需要访问主存，延迟增加数十倍           | 缺页需要访问磁盘，延迟增加可达十万倍，对系统性能影响较重                |
| Cpu 可直接访问 Cache 和主存 | Cache 不命中时，硬件可以自动从主存取出数据并装入 Cache 中 | 辅存与 CPU 没有直接通路，缺页时必须先将数据从辅存调入主存，之后 CPU 才能访问 |

*高速缓存Cache 具有比主存更快的存储速度，因此在 CPU 和主存之间设置它可以显著提升计算机整体的存储效率。Cache 由 SRAM 组成，一般集成在 CPU 的内部*
# I. 程序访问的局部性原理（重要‼️）

## 1. 时间局部性

+ 基本定义：时间局部性是指如果某条指令或数据项当前被访问，在不久的将来可能会**再次被访问**。
+ 特征：常源于程序中有循环♻️，重复调用的子程序，以及对同一数据的多次操作。
+ 简单说，最近要用到的信息，很可能是现在正在使用的信息ℹ️，比如说循环结构的指令代码
## 2. 空间局部性

+ 基本定义：如果某存储单元被访问，则其**邻近的存储单元**在不久的将来很可能也会被访问
+ 特征：指令通常顺序存放并顺序执行，而数据(如数组array，向量vector) 也往往以连续块的形式存储。
+ 基于局部性原理，不难想到，可以把 CPU 目前访问的地址“周围”的部分数据放到 Cache 中
高速缓存技术正是很好的利用了局部性原理，将程序当前活跃的部分数据暂存于容量小但速度极快的 Cache 中，使CPU 的多数访存操作直接在 Cache 中完成，显著提升了计算机存储系统的执行效率。

举例一🌰：
程序一：

```cpp 
int sum_array_rows(int a[M][N])
{
	int i,j,sum = 0;
	for(i=0; i<M; i++)
		for(j=0; j<N; j++)
			sum += a[i][j];
	return sum;
}
```
程序二：

```cpp 
int sum_array_cols(int a[M][N])
{
	int i,j,sum = 0;
	for(i=0; i<N; i++)
		for(j=0; j<M; j++)
			sum += a[i][j];
	return sum;
}
```

|       | 程序一                                                                                                        | 程序二                                                                                                                                  |
| ----- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 空间局部性 | 第一个程序中的数组按按行进行访问，`a[1][2],a[1][3],a[1][n]`的形式进行访问，依次可以遍历数组中的相邻元素，元素之间的存储密度很高，可以对数组进行顺序读取和访问，因此程序一的空间局部性很高。 | 第二个程序中的数组按按列进行访问，`a[1][2],a[2][3],a[2][n]`的形式进行访问，数组中的元素是按照列来排列的，访问顺序和存放顺序不一致；具有一定的跳跃性和离散性，读取的顺序需要跨过一行读取每个列的元素，相对于程序一来说，程序二的空间局部性很差。 |
| 时间局部性 | 单从数组元素的访问来看，因为这里的每个数组元素`a[n][m]` 仅访问一次，时间局部性都不是很好                                                          | 但是从 for 循环 的指令来看，循环指令都会在一定的范围内顺序反复执行，因此两个程序的时间局部性都是很好的。                                                                              |

# II. Cache的基本工作原理

*为了方便Cache 和主存之间进行数据交换，Cache 和主存都被划分为大小相等的块，Cache 块也称为 Cache 行，每块由若干字节组成。块的长度称为块儿长，也称为行长。因为 Cache 的容量很小，所以 Cache 的块数也远少于主存的块数。*

*另外，Cache 中保存的是主存中最活跃的，最经常被访问的内存块的副本。因此 CPU 自己也有一套策略，可以精准预测即将访问主存中的哪些数据，并将他们装入Cache。*
## 1. Cache访问过程

1）当进程送入 CPU，CPU 执行程序时，每当需要从主存取指令或读写数据的时候，CPU 首先访问的就是 Cache。
2）若信息早已在 Cache 中（Cache hit Cache 命中🎯）则直接从 Cache 读取，不需要访问主存。
3）如果没有命中（也叫缺失），则需要在主存中将该地址所在的主存块*整体* 调入 Cache，并将该块写入一个 Cache 行，如果此时 Cache 已满🈵，乘不下了。就需要用 LRU 等替换算法将最久没有用过块换出去，这个后面再说。
4）CPU 再从 Cache 块中获取相关数据。
整个访问过程（包括命中的判断、块调入、替换等）必须在单条指令执行周期完成✅
所以⬇️
***要特别注意：这条机制是完全用硬件实现的，对程序员是透明的，程序员不需要关心内部是如何工作的。*** 

上述访问流程是先查 Cache，如果没有命中的话再访问主存，这是一般统考题的考察方式。在有些系统中采用“并行访问策略”，就是会同时查 Cache 和主存，如果命中🎯则提前终止主存访问。不过这种一般考试中不涉及。

## 2. Cache命中率分析

### a. Cache命中率的分析和计算

不废话，先摆明需要记住的公式，这些公式很重要，会考！‼️

> [!NOTE]
> Cache命中率：  ${H = N_{c} /(N_{c} + N_{m})}$
> N<sub>c</sub> 是 Cache 的命中次数 , 访问主存的次数为N<sub>m</sub>也就是未命中次数，
> 🎯命中时：CPU 直接从 Cache 中读取数据，读取的耗时被称为命中时间 T<sub>c</sub> (意为 Cache 的访问时间)
> 未命中时：需要先从主存中读取包含目标数据的一个主存块，并将这个主存块送入 Cache 中（CPU 不会直接访问主存内存的，一般都是先访问 Cache），再将所需要的数据送到 CPU。
> 总耗时：${T_{m} + T_{c}}$ 其中T<sub>m</sub> 为缺失损失，即为主存调入一个快所需要的时间。
> Cache-主存系统的平均访问时间为：
> ${T_{a} = HT_{c} + (1 - H)(T_{m} + T_{c}) = T_{c} + (1 - H)T_{m}}$
 
### b. Cache 缺失率对主存带宽的影响

根据 Cache 的读、写流程可以知道，实现 Cache 时需要解决以下几个**重要的问题**：
+ 数据查找 如何快速的判断 CPU 或进程所需要的数据是否在 Cache 中
+ 地址映射 主存块如何存放在 Cache 中，以及如何将主存地址转换为 Cache 地址
+ 替换策略 当 Cache 已经满了的时候，采用什么策略可以选择被替换的 Cache 行
+ 写入策略 如何保证主存和 Cache 数据一致性的条件下，尽可能高的提升写效率


## 3. Cache 与主存的映射方式

*因为 Cache 行数远少于主存块数，Cache 只能存放主存中部分块的副本。为了识别每个 Cache 行对应哪个主存块，需要为每行设置一个标记位，记录其主存块编号。同时设置一个有效位，用于指示该行数据是否有效。在主存系统启动或复位的时候，所有 Cache 行均无效；仅有当主存块号被装入某个 Cache 行后，其有效位才为 1。地址映射映射是指将主存的地址空间按照一定的规则映射到 Cache 的地址空间，即决定如何将主存中的主存块装入 Cache 中。*

下面详细说一下 Cache 与主存块常见的映射方式——直接映射、全相连映射、n路组相联映射
### a. 直接映射

先记一个非常重要的一个公式： Cache 块号 = 主存块号 % Cache 总块数 （其中的 mod 是取模操作）
这对后期理解这三个映射方式具有非常大的帮助

定义：主存中的每一块只能装入 Cache 中的唯一指定位置。如果该位置已经有内容，就会发生块冲突。此时**不需要任何替换算法**就可以将原块换出内存（无条件替换）。
特点：直接映射实现简单、但它的灵活性差，即使 Cache 中的其他行有空闲，也不能用于存放主存块，因此直接映射的块冲突的概率非常高，空间利用率也很低。

*注意⚠️后面讲的 TLB 快表没有直接映射，只有全相连映射和n路组相联映射两种方式*
直接映射关系可表示为：
<center>Cache 块号 = 主存块号 % Cache 总块数 </center>

*原理：设 Cache 共有 2<sup>c</sup> 行，主存共有2<sup>m</sup>块。则主存的第 0 块、第2<sup>c</sup> 块、第2<sup>c+1</sup>块......均映射到 Cache 的第 0 行：主存的第 1 块、第 2<sup>c+1</sup> 块、第2<sup>c+1</sup>+1 k块等均映射到 Cache 的第一行，以此类推。由此可见，主存块号的低c位即为对应的 Cache 行号。*
为了标识来源，每个 Cache 行设置一个长度为 t = m - c 的标记。当某主存块调入 Cache 后，将其块号的高t位存入对应的 Cache 行的标记字段中。

Cpu 访存过程：

+ 如果标记位不等或有效位为 0，则 Cache 未命中❌。CPU 需要从主存读取该地址所在块，并将它装入对应的Cache 行中，且将有效位设置为 1，并更新标记为地址高 t位。
+ 然后将调入CPU想要的数据（刚刚调入Cache 的主存块中的数据）

### b. 全相联映射

特征：主存中的每一块可以装入 Cache 中的任何位置。每一行的标记可以用来指出该行来自主存中的哪一块，因此 CPU 进行访存时需要与所有 Cache 行的标记进行比较。
优点：
1. Cache 块的冲突概率比较低，只要有空闲的Cache 行，就不会发生冲突（弥补了直接映射只能按顺序存，不能随便找空闲行存的缺陷）
2. 空间利用率高
3. 命中率高
缺点：
4. 标记的比较速度比较慢
5. 另外实现的成本比较高（需要相应的硬件实现），通常需要使用按内容寻址的相联存储器

全相连映射方式的地址结构：

![[Pasted image 20260905011724.png|560]]

CPU 的访存过程：
1. 首先将主存地址的高位标记与 Cache 各行的标记进行比较。*注：位数 = log<sub>2</sub>主存块数 *
2. 如果有一个相等且对应有效位为 1，则 **Cache 命中🎯**，并根据块内地址从该Cache行中取出信息。
3. 若都不相等或有效位为0，则 **Cache 未命中**，CPU 此时会从主存中读出该地址所在的一块信息并将它装入 Cache 的任意一个空闲行，设置其有效位为 1，并设置标记，同时将所需要的数据送至 CPU。
### 根据地址结构和比较器数量判断映射方式

通常为每个 Cache 行都设置一个比较器，**比较器的位数等于标记字段的长度**。访存时根据标记字段的内容访问 Cache 行中的主存块，因此其查找过程是一种**按内容访问**的存取方式，属于相联存储器。
不足之处在于——这种方式的时间开销和硬件开销都很大，不适合大容量的 Cache。

### c. 组相联映射（包括二路组相连映射）`两种映射方式的折中`

*组相联映射实际上是介于前面两种方式的中和，也是基于成本💰(全相联映射成本过高，标记费时)和效率考虑的*
### 组相联映射的原理

先说这种映射方式的特点，简单说就是——Cache 块内分为若干组，每个主存块可放到特定分组中的任意一个位置，其中 组号 = 主存块号 % 分组块号。（这个方便和前面两种映射方式做区分，方便记忆）

将Cache划分为 Q 个大小相等的组，每个主存块只能映射到**固定组**中的任意一行，即组间采用直接映射，组内采用全相联映射。组相联映射是直接映射和全相联映射的一种折中方案；
当 Q=1时(整个 Cache 为一个组)，退化为全相联映射。当 Q = Cache 总行数(每组仅有 1 行)时，退化为直接映射。
设每组包含r个 Cache 行，则称为r路组相联映射。
其中路数r越大，组内可选位置越多，块冲突的概率就越低，但所需要的***比较器***数量和控制逻辑也越复杂。合理选择路数r，可以在硬件成本接近直接映射的同时，获得接近全相联映射的性能。

### 组相联映射的访存过程及 Cache 缺失处理过程

CPU 的访存过程：
+ 首先根据访存地址中的组号字段确定目标 Cache 组
+ 将该组内所有 Cache 行的标记与主存地址的高位标记并进行**行比较**，如果某行标记匹配且其有效位为 1，则 Cache 命中🎯，根据块内地址从该行读取数据。
+ 如果所有行均不匹配或匹配行的有效位为 0，则 Cache 未命中❌，CPU 从主存读取该地址所在块，将其装入该组中任意一个空闲行(若没有空闲行，则按替换算法选择一行)，并置其有效位为 1，写入标记，并将所需要的数据送至 CPU。
### 组相联映射中比较器的个数和位数

直接映射中每块仅对应一个唯一的 Cache 行，因此只需要设置1 个比较器。而r路组相联映射需要在同一组的r个 Cache 行中进行行比较，因此需要设置r个比较器。

> [!NOTE]
> 注意⚠️：无论是 DRAM 还是 SRAM，都是以行为单位进行比较，并且刷新也是按行进行刷新。
> 

### 三种映射方式总结

在 Cache 容量和主存块大小固定的条件下，三种映射方式的特性对比：

|           | 直接映射   | 全相联映射  | n 路组相联映射 |
| --------- | ------ | ------ | -------- |
| 命中率       | 最低⬇️😭 | 最高⬆️😄 | 介于两者之间☯️ |

+ 如果使用到了回写法，是一定要有**脏位**（修改位）的，如果脏位为 1，代表该行数据已经被修改，替换的时候必须要写回主存。如果为 0，则行数据与主存一致，替换的时候就可以直接覆盖。

## 5. Cache中的主存块替换算法

*Cache 很小，主存和辅存都很大。Cache 满了怎么办？*

使用替换算法的条件：
在采用全相联映射和组相联映射的方式时，当向 Cache 传送一个新主存块时，Cache 已经满了。这时候就需要使用替换算法选择被替换的 Cache 行。

**直接映射不需要使用替换算法，每个主存块只能映射到唯一的Cache 行，因此当该行被占用时，新块直接覆盖旧块就可以**

#### 补充：替换算法解决的问题：

+ Cache 完全满了才需要替换，需要在全局选择替换哪一块（a全相联映射）
+ 如果对应位置非空，就使用直接替换
+ 分组内满了才需要替换，需要在分组内选择替换哪一块(组相联映射)

#### 关于“抖动”现象

因为Cache 与主存块之间的替换会使用到不同的算法，例如RAND、FIFO 和 LRU 替换算法，因为不同的算法对主存块换入换出的处理逻辑不同，有些换出主存块比较频繁的算法就可能会间接地影响甚至削弱 Cache 的访存性能。

**抖动**，就是指 Cache 内的主存块在算法的影响下，频繁的换入换出，刚被替换的快很快又被调入。频繁的访问主存块数量＞(大于) Cache 行的数量很可能会引发抖动。

以下为常用的替换算法：
#### 随机替换算法

原理：随机选择一个 Cache 行进行替换，实现最简单。但是命中率比较低❌。没有利用程序访问的局部性原理。
#### FIFO先进先出替换算法

原理：替换最早装入的 Cache 行，实现比较容易。但同样没有考虑到局部性原理，最早进入的块可能仍是当前的热点数据，命中率并不高。
#### LRU最近最少使用替换算法

原理：基于程序访问的局部性原理，优先替换最近最久未被访问的 Cache 行。平均命中率要高于 FIFO。
这里很重要，我们给一个计算的例子🌰，选择题和大题的小问常考：


#### 最近不经常使用(LFU)算法

原理：替换一段时间内累计访问次数最少的 Cache 行。每行设置一个计数器，新行装入时计时器初始化为 0，每次访问该行则计数器+1；替换时选择计数值最小的行。LFU 和 LRU 的思想不同：LRU 关注最近是否用过，LFU 关注总共用了多少次。

*这个很少用，而且这个算法如果频繁访问主存块数量＞Cache 行的数量的时候会发生抖动现象。而且 LFU 算法实际上并没有遵守局部性原理，实际运行效果不如 LRU。*

#### 几种替换算法的汇总

|             | RAND 随机算法          | 先进先出 FIFO 算法    | 最近最少使用算法 LRU                       | 最不经常使用算法 LFU             |
| ----------- | ------------------ | --------------- | ---------------------------------- | ------------------------ |
| 算法运行流程      | 随机选择一个 Cache 行进行替换 | 替换最早装入的 Cache 行 | 基于程序访问的局部性原理，优先替换最近最久未被访问的 Cache 行 | 替换一段时间内累计访问次数最少的 Cache 行 |
| 命中率         | 低                  | 不高              | 高于 FIFO                            | 一般，比 LRU 低               |
| 是否会产生“抖动”   | 会                  | 会               | 有，但相对会好一些                          | 会                        |
| 是否基于“局部性原理” | ❌                  | ❌               | ✅                                  | ❌                        |

## 6. Cache 一致性问题 (Cache 写策略)

*简单来说，就是 CPU 修改了 Cache 中的数据副本，如何确保主存中数据母本的一致性的问题是主存与 Cache 相互协调工作的关键，而且这部分与 TLB 也有些关系*

根据写操作是否命中🎯Cache 有两种情况：一种是写命中，即 CPU 要写入的主存地址所在的块当前已经在 Cache 中，不需要再从主存里面去调用，相反另一种另一种则是写不命中；就是 CPU 要写入的主存地址所在的块不在 Cache 中。
### Cache写命中的方法
#### 直写法(也称为全写法，写直通法, Write Through)

当 CPU 对Cache 写命中时，数据同时写入 Cache 和主存。因为主存始终与 Cache 保持同步关系。因此在替换 Cache 块的时候，可以直接进行覆盖，不需要将块再写回主存（不需要写回）。
优点：这种方法实现简单，能够保证主存数据的实时准确性。
缺点：每次写操作都需要访问主存，降低了系统性能。

为了改进直写法，软件界有句俗语：“没有什么是加一个中间层办不到的“。就跟数据库与客户端访问需要中间加一个`Redis`内存缓存数据库一样。或者说就跟 Cache 与主存的关系一样，Cache充当速度缓冲区。

现在我们可以在 Cache 与主存之间再加一个缓冲区——写缓冲(write buffer)。CPU 将数据同时写入 Cache 和写缓冲，由写缓冲异步地将数据写入主存。写缓冲可以最大限度的缓解CPU 与主存之间的速度差异。但是再**高频度的写操作下，写缓冲可能会发生溢出。**

#### 回写法 (有些书也叫做写回法, Write Back) ❗️重要真题考过简答

当 CPU 对 Cache 写命中时，只将数据写入 Cache，不立即写入主存，仅在该块被替换出 Cache 的时候才写回主存。
优点：这种方式降低了访问主存的次数，显著的提升了Cache 的效率
缺点：存在数据不一致的缺陷。
解决办法：为了不避免的写回操作，每个 Cache 行设置一个修改位（脏位），**如果脏位是 1**，表示该行数据已经被修改，替换时必须要写回主存；**如果脏位是 0**，则表示该行数据与主存是一致的，替换时可以直接覆盖，**更重要的是，直写法不需要脏位，因为主存始终同步，写回法必须要设置脏位。**

### Cache写“不命中”的方法
#### 写分配法(Write Allocate)

当发生写不命中的时候，先将数据写入主存对应的单元，让后将该主存块调入 Cache 的一个空闲行中。这种方法利用了**空间局部性**，但每次写不命中都要将主存块加载到Cache 中

#### 非写分配法(Not-Write-Allocate)

当发生写不命中的时候，直接将数据写入主存，不将主存块调入 Cache
## 7. Cache的应用
### a. 分离Cache

随着指令流水技术的发展，现代处理器通常将指令Cache 和数据Cache 分开设计，形成分离的Cache 结构。统一Cache 的优点在于其设计和实现相对简单，但在流水线执行中，取指部件和执行部件同时访问同一Cache 时容易产生冲突。通过采用分离Cache 结构，不仅可以消除这类冲突，还能针对指令和数据的不同局部性特征进行优化，从而提升整体性能。

### b.多级Cache

现代计算机普遍采用多级Cache结构。以两级例，按距离CPU的远近分别称为LI Cache和L2 Cache: LI 离 CPU 最近，速度最快、容量较小；L2则较远，速度较慢、容量较大。通常情况下，L1级会采用分离的指令 Cache 和数据Cache 设计，其中LI 数据 Cache 在写操作中采用写分配法（写不命中时加载块）与回写法（写命中时不立即写主存）相结合的策略。

图3.25展示了一个典型的两级 Cache 系统。通常，L.1 和L2 Cache 均采用回写法，当L1发生写命中时，仅更新L1；当LI块被替换时，若脏块，则写回L2；L2同理，在替换时写回主存。由于L2 Cache 的访问速度远高于主存，L1无须在写命中时访问主存，仅更新本地 Cache即可快速完成写操作；后续的脏块写回由L2高效承接，从而有效避免因频繁写操作导致的写缓冲饱和或溢出问题。
